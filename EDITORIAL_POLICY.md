# World Myth Archive — Editorial Policy

## Source Inclusion Criteria

### Public Domain or Open Access Only
All full-text works must be in the public domain or explicitly licensed for redistribution. When no lawful public-domain translation exists, the work is kept as `metadata_only` with a clear rights note.

### Translation Choice
- Prefer scholarly, complete translations in English
- Accept abridged renderings only when clearly marked (`completeness: abridged`)
- Carry translator, publisher, publication date, and source URL in every work's provenance
- When multiple PD translations exist, prefer the one most widely cited in scholarship

### Textual Integrity
- Strip publisher front matter, tables of contents, footnotes, endnotes, and license blocks
- Preserve lacunae and fragmentary passages when noted by the translator
- Maintain stanza/line numbering where it exists in the source

## Tagging Policy

### Controlled Vocabularies
All tags draw from eight controlled lexicons in `Corpus Forge/lexicons/`:

1. **Myth Type** — genre classification (cosmogony, hero saga, ritual text, etc.)
2. **Theme** — narrative themes (creation, flood, hero journey, etc.)
3. **Character Archetype** — Jung/Campbell-derived and culture-specific archetypes
4. **Social Role** — Dumézil functions and related social functions
5. **Cognitive Function** — cognitive-science interpretations (agency detection, memory transmission, etc.)
6. **Rite** — ritual categories (sacrifice, initiation, funeral, etc.)
7. **Myth Episode** — narrative episode types (monster slaying, underworld journey, etc.)
8. **Proppian Function** — Vladimir Propp's 31 narrative functions

### Work-Level Tags
- Assigned manually during ingestion based on scholarly consensus about the work
- Must use codes from the controlled lexicons
- No more than 4–5 tags per category per work

### Chunk-Level Tags
- Generated by automated heuristic matching against chunk text and section headings
- Scored from controlled-vocabulary keywords, custom phrase lists, and work-level tag bonuses
- Frequency-damped per work to prevent ultra-generic tags from dominating
- **Treated as discovery aids, not scholarly claims**

### Confidence and Review Stages

| Stage | Meaning | Confidence Base |
|-------|---------|-----------------|
| `raw` | Text exists, not cleaned | 0.15 |
| `cleaned` | Readable Markdown | 0.35 |
| `metadata_complete` | Work-level tags and provenance present | 0.50 |
| `machine_tagged` | Automated chunk tags generated | 0.62 |
| `human_reviewed` | Human editor reviewed text and tags | 0.82 |
| `scholar_reviewed` | Domain specialist reviewed | 0.95 |

All 25 current works are at `machine_tagged`.

### Ad-Hoc Tag Handling
- Ad-hoc tags invented outside the controlled lexicons are mapped to approved codes or removed
- New codes may be added to lexicons only when they represent a genuinely distinct, reusable concept
- The `addWorkTagsToLexicons()` function in the build pipeline dynamically registers unknown tags to prevent crashes, but these are flagged for normalization

## Entity Extraction

- Entities (figures, creatures) are matched from `key_figures.csv` and `creatures.csv`
- Matching is string-based against normalized names
- The entity lexicon is intentionally conservative; missing entities are expected
- Future work: expand entity coverage or add named-entity recognition

## Human Review Gold Set

A future milestone. We aim to produce a 50–100 chunk human-reviewed gold set across cultures to evaluate automated tag accuracy. Until then, all chunk tags carry the caveat:

> "Tags are machine suggestions from controlled lexicons and should be treated as interpretive aids until human-reviewed."

## Completeness and Abridgment

| Status | Meaning |
|--------|---------|
| `complete` | Full text of the selected recension |
| `partial` | Missing books, cantos, or kandas |
| `abridged` | Condensed prose rendering |
| `metadata_only` | No full text ingested (rights or source gap) |
| `not_ingested` | Work moved out of corpus pending source |

## Updates and Versioning

- `corpus_manifest.json` is the authoritative source/status record
- `search-index.json` is regenerated from scratch on every data build
- Work Markdown files are the canonical text layer
- All changes to source texts or tags require re-running `npm run generate:data`
